# Чат (реєстрація за юзернеймом + реальний час)

Стек: Node.js + Express + Socket.io, SQLite (better-sqlite3), vanilla JS фронтенд.

## Що вміє

- Реєстрація/логін за юзернеймом і паролем (пароль хешується bcrypt)
- Пошук людини за юзернеймом
- Створення чату з людиною і збереження всієї переписки в SQLite
- Доставка повідомлень співрозмовнику миттєво (Socket.io), без перезавантаження сторінки
- Список чатів з останнім повідомленням
- Надсилання фото в чаті (jpeg/png/gif/webp, до 8 МБ)
- Перегляд фото на весь екран з кнопками "Переслати" і "Завантажити"
- Пересилання будь-яких повідомлень (текст і/або фото) в інший чат
- Групове виділення повідомлень (чекбоксом) з масовим пересиланням/видаленням
- Видалення власних повідомлень (видаляються одразу в обох учасників чату)
- Надсилання аудіофайлів (mp3/wav/ogg/m4a/aac, до 20 МБ) з власним плеєром і повзунком гучності
- Запис голосового повідомлення прямо в браузері (мікрофон) з індикатором запису й таймером
- Аватарка профілю (завантаження/зміна/видалення) — видно в списку чатів і в шапці чату у співрозмовника
- Кнопка завантаження біля аудіоповідомлень
- Надсилання відео (до 500 МБ) з прев'ю перед відправкою і повноекранним переглядом
- Статуси прочитання повідомлень: одна галочка — надіслано, дві (кольорові) — прочитано співрозмовником
- Миттєве оновлення аватарки співрозмовника в списку чатів і шапці чату без перезавантаження сторінки
- Вставка картинки з буфера обміну (Ctrl+V) прямо в чат
- Одночасно грає лише одне голосове/аудіо; єдиний регулятор гучності в шапці чату для всіх голосових
- Меню вкладень (скріпка) замість окремих кнопок — фото, відео, аудіофайл і голосове в одному випадаючому списку
- Поле вводу саме росте до ~4 рядків тексту, далі — прокрутка всередині нього
- Видалення повідомлень з вибором: "для мене" (зникає лише у видаляючого) або "для всіх" (лише власні повідомлення, видаляються остаточно для обох)
- Видалення всього чату правим кліком/довгим натисканням у списку — "для мене" (чат ховається, повертається при новому повідомленні) або "для обох" (видаляється остаточно з усією історією)
- Базовий набір стікерів (кнопка 😊 біля поля вводу)
- Реакції на повідомлення (❤️ 👍 🔥) — правий клік по повідомленню
- Статус "у мережі" / "був(ла) недавно" / час останнього заходу — з можливістю приховати активність у налаштуваннях профілю. Якщо співрозмовник прямо зараз дивиться відкритий чат з вами — показує "у мережі" завжди, незалежно від приватності

## Запуск локально

```bash
npm install
cp .env.example .env
# відкрий .env і зміни JWT_SECRET на щось випадкове
npm start
```

Відкрий http://localhost:3000

## Структура

```
chat-app/
  server.js       — Express API + Socket.io
  db.js           — ініціалізація SQLite (users, chats, messages)
  public/         — фронтенд (index.html, style.css, app.js)
  .env.example    — приклад змінних оточення
```

## Деплой на Railway

1. Заведи git-репозиторій і залий цей проєкт на GitHub (Railway деплоїть з git).
2. На railway.app: New Project → Deploy from GitHub repo → обери свій репозиторій.
3. Railway сам розпізнає Node.js проєкт (є `package.json` з `start` скриптом) і задеплоїть.
4. У Variables додай:
   - `JWT_SECRET` — довгий випадковий рядок (наприклад згенерований `openssl rand -hex 32`)
5. Railway сам підставить змінну `PORT` — сервер вже налаштований її використовувати.

### Важливо про базу даних SQLite на Railway

Файлова система Railway за замовчуванням **ефемерна** — при кожному новому деплої файл `data.db` (а разом з ним усі акаунти й переписка) буде втрачено. Є два варіанти:

**Варіант A — Railway Volume (найпростіше, залишаємось на SQLite):**
1. У сервісі відкрий Settings → знайди розділ Volumes → Create Volume → вкажи mount path, наприклад `/data`.
2. Додай змінну оточення `DB_PATH=/data/data.db`.
3. Якщо хочеш, щоб завантажені фото теж не губились при редеплої, додай ще `UPLOAD_DIR=/data/uploads` (той самий volume, інша підпапка).
4. Тепер база і фото зберігатимуться між деплоями.

Без `UPLOAD_DIR` фото зберігаються у звичайній файловій системі контейнера і будуть губитись при кожному новому деплої — так само, як губилась база без `DB_PATH`.

**Варіант B — перейти на PostgreSQL (надійніше для продакшн):**
Railway дає безкоштовний Postgres-аддон одним кліком. Якщо захочеш — можу переписати `db.js`/`server.js` під PostgreSQL (бібліотека `pg`), запити майже не зміняться.

### Про запис голосових

Браузери дозволяють доступ до мікрофона (`getUserMedia`) лише на HTTPS або на `localhost`. На Railway домен завжди HTTPS, тож проблем бути не повинно — це важливо тільки якщо тестуєш через IP-адресу без HTTPS.
